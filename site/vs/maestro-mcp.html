simulator-use vs Maestro MCP

Pick Maestro if you want tests as Maestro flows: YAML files kept in the repo and run locally or on Maestro Cloud, on Android, iOS and web. (Maestro README, Maestro docs: Maestro MCP)

Pick simulator-use to build the app and run its XCTest and XCUITest cases, and to read and act on the screen with single calls instead of flows. (simulator-use README, Maestro docs: build your app for the cloud)

Measured on one Mac, a sign-in took Maestro MCP 9.00 s and 2,987 tokens read (est.); simulator-use 4.66 s (second run 7.13 s) and 194 tokens read (est.).

Where Maestro MCP is better

  • Tests are flows, a flat list of YAML commands, that run the same locally and on Maestro Cloud. (Maestro README, Maestro docs: Maestro MCP)
  • Android emulators, iOS simulators and Chromium for web from one server. (Maestro docs: Maestro MCP)
  • Reading the screen: 0.11 s against simulator-use's 0.21 s (second run 0.22 s).

Where simulator-use is better

  • Builds the Xcode project and runs its XCTest and XCUITest cases. (simulator-use README)
  • No Java needed; Maestro needs Java 17. (simulator-use README, Maestro README)
  • Signing in, step by step: 4.66 s (second run 7.13 s) against Maestro MCP's 9.00 s.
  • Tokens read per sign-in (est.): 194 tokens against Maestro MCP's 2,987 tokens.
  • Signing in, batched: 3.69 s (second run 5.36 s) against Maestro MCP's 7.69 s.
  • Tokens per screen read (est.): 72 tokens against Maestro MCP's 1,107 tokens.
  • Tapping a button: 1.17 s (second run 1.10 s) against Maestro MCP's 1.59 s.
  • Typing into a field: 1.22 s (second run 2.28 s) against Maestro MCP's 3.68 s.
  • Tool list in the agent's context (est.): 2,443 tokens against Maestro MCP's 3,063 tokens.
  • A tap's answer held the new status text in 20 of 20 taps, Maestro MCP's in 0 of 20.

A measured difference is listed only when it holds against both of simulator-use's runs by at least 5%.
