simulator-use vs AXe

Pick AXe for a command line with no MCP server: shell scripts, CI jobs, or agents that run commands. simulator-use is built on AXe's frameworks. (AXe docs, simulator-use README)

Pick simulator-use for an MCP server on the same frameworks that also builds and tests the app and reads the screen as one line per element. (simulator-use README)

Measured on one Mac, a sign-in took AXe 9.22 s and 110,319 tokens read (est.); simulator-use 4.66 s (second run 7.13 s) and 194 tokens read (est.).

With Device Hub open

AXe's README says:

"Xcode 27 simulator automation uses Device Hub; Simulator.app is not required." (AXe README)

So AXe ran three times on the benchmark's Mac: with the Simulator headless like every tool, again with Device Hub open, and once more with Device Hub closed. The ranking uses the first run.

Where AXe is better

  • Screenshots, video recording and frame streaming from the same command. (AXe docs)
  • Tool list in the agent's context (est.): none, since AXe is a command line with no MCP server, against simulator-use's 2,443 tokens.

Where simulator-use is better

  • An MCP server, building and testing the Xcode project, on AXe's own frameworks. (simulator-use README)
  • Signing in, step by step: 4.66 s (second run 7.13 s) against AXe's 9.22 s.
  • Tokens read per sign-in (est.): 194 tokens against AXe's 110,319 tokens.
  • Reading the screen: 0.21 s (second run 0.22 s) against AXe's 0.84 s.
  • Tokens per screen read (est.): 72 tokens against AXe's 44,869 tokens.
  • Tapping a button: 1.17 s (second run 1.10 s) against AXe's 1.67 s.
  • A tap's answer held the new status text in 20 of 20 taps, AXe's in 0 of 20.

A measured difference is listed only when it holds against both of simulator-use's runs by at least 5%.
