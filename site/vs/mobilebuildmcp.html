simulator-use vs MobileBuildMCP

Pick MobileBuildMCP for a wider Xcode workflow from one server: builds for the Simulator, devices and macOS, Swift packages, code coverage and LLDB debugging. (MobileBuildMCP workflows)

Pick simulator-use for driving the Simulator's screen: it reads and taps through its own long-lived engine on AXe's frameworks, where MobileBuildMCP asks its bundled AXe for each read and action. (simulator-use README, MobileBuildMCP docs: UI automation)

Measured on one Mac: simulator-use read 194 tokens per sign-in, MobileBuildMCP 1,561 (est.); simulator-use signed in in 3.50 s, MobileBuildMCP in 12.26 s.

Before version 2.7.1, MobileBuildMCP was called XcodeBuildMCP; its changelog for 2.7.1: "Renamed the project from XcodeBuildMCP to MobileBuildMCP." (MobileBuildMCP CHANGELOG)

With Device Hub open

MobileBuildMCP reads and taps through a bundled AXe, and AXe's README says:

"Xcode 27 simulator automation uses Device Hub; Simulator.app is not required." (AXe README)

Its own changelog, for version 2.7.0: "UI automation tools now work fully with Xcode 27 simulators through Device Hub" (MobileBuildMCP CHANGELOG).

So MobileBuildMCP ran three times on the benchmark's Mac: with the Simulator headless like every tool, again with Device Hub open, and once more with Device Hub closed. The ranking uses the first run.

With Device Hub open, every tap still answered that it was done; the counts are what the app's own log saw. simulator-use is built on AXe's frameworks: its engine keeps one session open per Simulator instead of starting AXe for each call.

Where simulator-use is better

  • Typing is one call per field that reads the text back. MobileBuildMCP's refs belong to its latest snapshot and its tools say to refresh after layout changes, so in the benchmark it read the screen again after each typing (counted in its sign-in). (simulator-use README, MobileBuildMCP's tap tool)
  • Signing in, step by step: 3.50 s against MobileBuildMCP's 12.26 s.
  • Tokens read per sign-in (est.): 194 tokens against MobileBuildMCP's 1,561 tokens.
  • Reading the screen: 0.19 s against MobileBuildMCP's 0.62 s.
  • Tokens per screen read (est.): 72 tokens against MobileBuildMCP's 386 tokens.
  • Tapping a button: 0.68 s against MobileBuildMCP's 2.37 s.
  • Typing into a field: 1.14 s against MobileBuildMCP's 3.15 s.
  • Tool list in the agent's context (est.): 2,443 tokens against MobileBuildMCP's 6,193 tokens.
  • A tap's answer held the new status text in 20 of 20 taps, MobileBuildMCP's in 0 of 20.

A measured difference is listed when it is 5% or more.
