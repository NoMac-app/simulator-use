simulator-use vs ios-simulator-mcp

Pick ios-simulator-mcp for a small set of Simulator tools on Facebook's IDB that also shows the agent a screenshot (ui_view), records video, opens deep links and pastes text on non-US keyboard layouts. (ios-simulator-mcp README)

Pick simulator-use to build and test the Xcode project with the same tool, to get the screen as one line per element, and to tap by label or id instead of at coordinates, with nothing to install besides Node. (simulator-use README, ios-simulator-mcp README, ios-simulator-mcp TROUBLESHOOTING (installing IDB))

Measured on one Mac: simulator-use read 194 tokens per sign-in, ios-simulator-mcp 5,248 (est.).

Where simulator-use is better

  • Builds the Xcode project, installs and launches it, and runs its XCTest and XCUITest cases; ios-simulator-mcp installs an app built elsewhere. (simulator-use README, ios-simulator-mcp README)
  • Taps go to an element by #id or label; ios-simulator-mcp taps at coordinates the agent works out from the frames in the tree. (simulator-use README, ios-simulator-mcp README)
  • Nothing to install besides Node: its engine bundles AXe's frameworks, the IDB frameworks among them. ios-simulator-mcp needs idb_companion from Homebrew and the fb-idb Python client. (simulator-use README, ios-simulator-mcp TROUBLESHOOTING (installing IDB))
  • Tokens read per sign-in (est.): 194 tokens against ios-simulator-mcp's 5,248 tokens.
  • Tokens per screen read (est.): 72 tokens against ios-simulator-mcp's 891 tokens.
  • Tool list in the agent's context (est.): 2,443 tokens against ios-simulator-mcp's 2,655 tokens.
  • A tap's answer held the new status text in 20 of 20 taps, ios-simulator-mcp's in 0 of 18.
  • Taps that reached the app: 20 of 20 against ios-simulator-mcp's 18 of 20.

A measured difference is listed when it is 5% or more.

Switching

Add simulator-use to Claude Code with one line (other clients: install):

claude mcp add simulator-use -- npx -y simulator-use mcp
